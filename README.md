# Magic Mirror

Magic Mirror is a Windows utility for running multiple isolated Discord profiles from a single Discord installation.

Each profile receives its own local Discord data directory, allowing multiple Discord accounts to remain signed in separately without repeatedly logging in and out of the standard Discord client.

Magic Mirror can:

* Create and manage isolated Discord profiles.
* Launch multiple Discord instances using separate profile data.
* Detect whether each profile is stopped, running, or still active without a usable window.
* Safely stop and re-launch tracked Discord instances.
* Control profiles from the Windows system tray.
* Back up selected profiles.
* Recover from orphaned or stuck Discord processes.
* Persist process tracking across Magic Mirror restarts.
* Recover from damaged process-tracking state.
* Keep local diagnostic logs for troubleshooting.

> [!IMPORTANT]
> Magic Mirror is an independent project and is not affiliated with, endorsed by, or supported by Discord Inc.

## Profile sessions

New Magic Mirror profiles start with a blank Discord data directory.

The first time a profile is launched, Discord will normally require you to log into an account.

After a successful login, Discord stores its own local session data inside that profile. Future launches of the same Magic Mirror profile will therefore normally reopen the Discord account previously used with it.

For example:

```text
Profile A → Log into Discord account A
Profile B → Log into Discord account B

Later:

Profile A → Discord normally opens account A
Profile B → Discord normally opens account B
```

Magic Mirror itself does not ask for or store your Discord password.

Discord may still require authentication again if the session expires, is revoked, or Discord otherwise invalidates it.

Because profile directories contain local Discord data, **they should be treated as private files**.

## Backups

Magic Mirror can copy selected profiles to a folder chosen by the user.

Only profiles that are not currently running can be backed up. This prevents Discord from modifying databases, caches, session storage, or other profile files while they are being copied.

Backups are direct copies of the profile directories.

> [!CAUTION]
> Profile backups may contain private Discord data, cached content, identifiers, settings, session-related information, and other local application data.
>
> Store backups somewhere you trust and do not publish or casually share them.

Magic Mirror does not sanitize profile contents before creating a backup.

## How profile isolation works

Profiles are stored under:

```text
%LOCALAPPDATA%\Discord\Profiles\<ProfileName>
```

Discord is launched through its normal installed launcher:

```text
%LOCALAPPDATA%\Discord\Update.exe
```

The relevant launch logic is primarily implemented in:

```text
MainForm.LaunchProfileAsync()
```

Before starting Discord, Magic Mirror sets the profile-specific Discord user-data directory:

```csharp
startInfo.Environment[
    "DISCORD_USER_DATA_DIR"
] = profilePath;
```

Discord is then started through `Update.exe` using:

```text
--processStart Discord.exe --process-start-args "--multi-instance"
```

Conceptually:

```text
Magic Mirror
    │
    ├── Select profile directory
    │
    ├── Set DISCORD_USER_DATA_DIR
    │
    └── Start Discord\Update.exe
            │
            └── Discord.exe --multi-instance
```

Each Discord instance therefore receives a different local user-data directory while still using the same installed Discord application.

Magic Mirror does not modify `Discord.exe` and does not maintain a separate Discord installation for every profile.

## Process and PID tracking

Discord is an Electron application and normally creates several `Discord.exe` processes for a single instance.

Because of this, Magic Mirror does not associate a profile with only one PID.

The primary launch-tracking implementation is located in:

```text
InstanceManager.TrackLaunchedInstanceAsync()
```

Before launching a profile, Magic Mirror records the Discord processes that already exist.

A process is only considered a valid Discord process when its executable can be verified as `Discord.exe` beneath:

```text
%LOCALAPPDATA%\Discord
```

Magic Mirror then launches `Update.exe` and records the launcher's PID.

New Discord processes are compared against the pre-launch baseline, and their Windows parent/child relationships are inspected. When a new Discord process group can be traced back to the launcher created for that profile, the group is associated with the profile.

If the launcher exits before its process relationship can be observed, Magic Mirror uses a conservative fallback that only accepts an unambiguous newly created Discord process group.

If ownership cannot be determined safely, Magic Mirror refuses to guess rather than risk associating the wrong Discord instance with a profile.

### Process identity

Each tracked process stores:

```text
PID
Process start time
Executable path
```

Before a tracked process is trusted again, Magic Mirror verifies that those details still match the running process.

This protects against situations where Windows reuses an old PID for an unrelated process.

Magic Mirror can also adopt Discord helper processes created later when they can be traced back to an already verified member of that profile's process group.

Tracking state is stored in:

```text
%LOCALAPPDATA%\Magic Mirror\instances.json
```

If this file becomes malformed or unreadable, Magic Mirror attempts to archive the damaged file and starts again with empty tracking state.

**Profile data is not deleted during tracking-state recovery.**

## Discord installation

Magic Mirror expects Discord's launcher at:

```text
%LOCALAPPDATA%\Discord\Update.exe
```

If it cannot be found, Discord-dependent actions are disabled rather than being attempted and failing later.

Existing profile folders can still be accessed and backed up.

Magic Mirror will not create a fake `%LOCALAPPDATA%\Discord` installation simply because Discord is missing.

## Emergency recovery

Magic Mirror includes two recovery tools for stuck or orphaned Discord processes.

### Nuke Non-Visible Discord Instances

Targets verified Discord process groups that no longer have a usable visible Discord window.

Discord groups that still have a usable window are left alone.

### Nuke All Discord Instances

Targets all processes that can be verified as genuine `Discord.exe` processes beneath the local Discord installation.

This is intended as an emergency recovery option when Discord's process state has become severely confused.

### These tools do not delete

* Discord profiles
* Profile folders
* Backups
* Discord accounts
* Profile data

They terminate verified processes only.

## Local files

Magic Mirror stores its own settings, process tracking, and logs under:

```text
%LOCALAPPDATA%\Magic Mirror
```

This can include:

```text
settings.json
instances.json
instances.corrupt.<timestamp>.json
Logs\
```

Discord profile data is stored separately under:

```text
%LOCALAPPDATA%\Discord\Profiles
```

Diagnostic logs may contain information such as profile names, process IDs, local file paths, launch results, recovery results, and application errors.

Review logs before posting them publicly if you consider any of those details private.

## Privacy

Magic Mirror contains no telemetry intended to send profile contents, backups, diagnostic logs, or usage information to the developer.

Magic Mirror itself does not transmit these files to external services.

When requested by the user, Magic Mirror starts the official Discord client. Discord then communicates with Discord's own services according to Discord's software, terms, and privacy policies.

Magic Mirror is not responsible for the behavior of the Discord client or Discord's online services.

---

## Updates and compatibility

Magic Mirror is designed to survive ordinary Discord updates because it launches the installed Discord client rather than maintaining or modifying its own Discord installation.

However, Discord may change its launcher, installation structure, process behavior, handling of multiple instances, or other implementation details in the future.

If Discord makes such a change, Magic Mirror may require an update.

After the initial release, Magic Mirror is expected to receive maintenance and compatibility fixes rather than frequent feature updates.

Further development will mainly depend on Discord compatibility changes, useful feature requests, bug reports, or outside contributions.

## Uninstallation

Exit Magic Mirror completely and remove the application files.

Magic Mirror's own settings, process-tracking data, and logs can be removed manually from:

```text
%LOCALAPPDATA%\Magic Mirror
```

Discord profiles are stored separately under:

```text
%LOCALAPPDATA%\Discord\Profiles
```

Do **not** delete that directory unless you intentionally want to remove the locally stored profiles.

Uninstalling Magic Mirror does not delete Discord accounts.
